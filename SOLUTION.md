Что было сделано

Исправлены баги в выводе, обновлении и отправке характеристик товара.

1. Вывод характеристик
SQL-инъекция. Исходный запрос строил cat_prop LIKE '%" . $categoryId . "%'" напрямую из $_POST. Убрал конкатенацию: теперь весь список характеристик (property_s) выбирается одним простым запросом без пользовательского ввода в SQL, а фильтрация по выбранным категориям выполняется в PHP.
Некорректное сравнение через LIKE. LIKE '%1%' совпадал не только с категорией 1, но и с 12, 21 и т.п. Заменил на точный разбор: cat_prop разбивается через explode(',', ...), каждый id приводится к (int) и сравнивается напрямую с выбранными категориями.
Общие характеристики не выводились. Добавлена явная проверка: если cat_prop пустой (или NULL) — характеристика выводится всегда, независимо от выбранных категорий (и в addNewGood.tpl.php, и в Refresh_Property_Good.php).
Дублирование характеристик. Раньше характеристика, привязанная сразу к нескольким выбранным категориям, могла отрендериться несколько раз. Теперь идёт один проход по всем характеристикам, и как только находится совпадение с выбранной категорией — break, повторных вставок нет.
XSS. Все текстовые значения из БД (name_prop, place_prop, answer_prop) выводятся через существующую функцию h(), HTML/JS больше не интерпретируется браузером.
Пустой/некорректный category. Добавлена проверка isset($_POST['category']) && is_array(...) перед обработкой — при отсутствии или некорректном формате параметра ошибок нет, возвращаются только общие характеристики.

2. Сохранение введённых значений
В property.js добавлены функции getStoredValues() / restoreValues():
перед AJAX-запросом снимается снимок текущих значений всех видимых характеристик (текст/число/select — через .val(), чекбоксы — через отмеченные data-val);
после обновления .property_all значения восстанавливаются для тех характеристик, что остались в новом наборе (сопоставление по data-property).

3. Проверка отправки (main.js)
Добавлена обработка мультивыбора (чекбоксов) — раньше она отсутствовала полностью. Отмеченные значения собираются по data-val и склеиваются через :::.
Пустые и отсутствующие в текущем наборе характеристики не попадают в property_mas.
Значение '0' явно проверяется как заполненное (сравнение с пустой строкой, а не приведение к boolean).
cats собирается по data-category-chpu, как того требует контракт Preview_Good_Payload.php.
